## Backlog

- **Instruction table: enforce mode (high):** report mode is built (`instruction_table = { path, sha256, mode = "report" }`, findings `instructions`, `accounts` and `profile` in reports and audit entries). Remaining: `mode = "enforce"`, which refuses on any finding (`feat!:`, since it refuses what was signed before), after report mode has run against real play long enough to show the table and forge-mcp's payloads agree ([Hardening proposals](https://ttdonovan.github.io/sa-forge-signer/dev/hardening.html), 4).
- **Redeploy watch and holds (low; high before mainnet):** read each game program's last-deploy slot from its program-data account; on a change, write a `program-redeploy` audit entry and, with `on_program_redeploy = "hold"`, refuse `auto` signs per instruction family until `programs accept` or a passing `canary` run over `canary_dir` (payloads with expected outcomes, where an unexpected success fails and an RPC error releases nothing) ([Hardening proposals](https://ttdonovan.github.io/sa-forge-signer/dev/hardening.html), 8).
- **Reserved headroom for recovery (optional, after the instruction table):** `reserved_per_minute` and `reserved_lamports` kept for messages whose game instructions are all in `reserved_families`, classified from the table, never from `summary` ([Hardening proposals](https://ttdonovan.github.io/sa-forge-signer/dev/hardening.html), 9).
- **Approval outside the terminal:** `confirm` reads `/dev/tty`, which an agent running as the terminal's user can type into through a multiplexer or a terminal app's scripting API, and which `serve` in a container usually lacks. Move approval to a channel that checks who answers, such as a Unix socket that accepts only a configured approver uid (peer credentials), so `confirm` keys also work under `serve`.
- **`serve` thread cap and RPC budgets:** one thread per request is unbounded today; cap concurrent requests and answer the rest with 503. `check` has no rate limit either: add `[serve] check_per_minute` per token (429), keep polling of already-sent transactions ahead of `check` and preflight RPC calls, and cache the genesis hash per process ([Hardening proposals](https://ttdonovan.github.io/sa-forge-signer/dev/hardening.html), 10).
- **SPL Token authority check:** refuse top-level SPL Token `Transfer` / `Approve` (and their `Checked` forms) whose authority is the signing key, using the public SPL Token instruction layout. Today such instructions pass on program id alone, so a hand-written payload could move tokens from a token account the key owns.
- **Key stores:** an encrypted-file backend (age, passphrase at `serve` start) and macOS Keychain / Secret Service backends, for running outside a container. Check first whether a Keychain item can be isolated from other processes of the same user. For age: write files at a scrypt work factor of at least 2^18 and refuse to load one below it; use age rather than an own Argon2id envelope; take the passphrase from the terminal or systemd credentials, never an environment variable or argument ([Hardening proposals](https://ttdonovan.github.io/sa-forge-signer/dev/hardening.html), 11).
- **Read-after-write (optional):** document the report's `slot` as the minimum context slot for the caller's next reads, and pass the key's last landed slot as `minContextSlot` on the signer's own pre-sign reads ([Hardening proposals](https://ttdonovan.github.io/sa-forge-signer/dev/hardening.html), 12).
- **systemd unit (low):** a chapter with an example hardened unit (dedicated user, `ProtectSystem=strict`, empty capabilities, `SystemCallFilter=@system-service`, `LimitCORE=0`, `MemorySwapMax=0`, `TimeoutStopSec=230`, `LoadCredentialEncrypted=` for the key passphrase) checked with `systemd-analyze security` ([Hardening proposals](https://ttdonovan.github.io/sa-forge-signer/dev/hardening.html), 13).
- **Secrets in memory:** `Keypair` already zeroes itself on drop (`solana-ed25519`'s default `zeroize` feature), and key files, payload text and partial signers are read into `Zeroizing` buffers. What is left: buffers that grow while being filled (`serde_json` parsing a key file into a `Vec<u8>`, `read_to_string` from stdin or an HTTP body) free copies that are never wiped, so reserve the full size up front; `serve`'s MCP route parses the request into a `serde_json::Value` that holds `partial_signers` and is dropped without wiping; and moves of a `Keypair` leave copies on the stack. Ahead of those, guard against copies outside the process: turn off core dumps (`RLIMIT_CORE` 0, and `PR_SET_DUMPABLE` 0 on Linux) and consider `mlock` for key pages so they are not swapped out. Low priority: all of this assumes a memory disclosure in a process the agent's OS user cannot read.
- **Local-validator integration tests:** prove the outcomes that only fake-chain unit tests cover today: `failed` (exit 12, landed with a program error), an expired blockhash with no status found (`unknown`, exit 14; exit 13 is retired), and the one-time re-sign on `BlockhashNotFound`.
- **Releases:** reproducible builds (verify two builds match byte for byte), an SBOM attested next to the provenance, and an external review before any mainnet use. Checksums and build provenance attestations ship with each release since v0.4.0.
